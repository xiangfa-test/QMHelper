# QMHelper 适配交接文档

> 写给下一个接手这个项目的 AI / 开发者。读完这篇你应该能在 10 分钟内恢复全部上下文并继续干活。
> 最后更新：2026-11-27，分支 `api102-qqmusic21`，模块 1.2.0(117)。

## 1. 项目是什么

上游 [zjns/QMHelper](https://github.com/zjns/QMHelper)（Q音助手，v1.1.4，2024-01）的**本地适配版**。
目标：让模块在新版 QQ音乐 上继续工作，并把模块 API 迁移到 libxposed **API 102**。

- 仓库本地路径：`default-workspace\QMHelper`
- 分支：`api102-qqmusic21`（从上游 v1.1.4 = `b3c38f3` 分出）
- 适配目标宿主：`com.tencent.qqmusic` **21.0.5.x**（模拟器上宿主会自动更新，当前 21.0.5.5 / 7755，适配时是 21.0.5.3 / 7753）
- 参考项目（用户自己的旧作，可借鉴思路）：`default-workspace\QQMusicPlus`（包名 com.xiang.qqmusicplus）

## 3. 构建系统要点

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\build_and_install.ps1
# 可选：-SkipBuild（只装不编）  -DebugBuild（强制装 debug）  -BuildOnly  -WaitSeconds N  -Serial xxx
```

- **一次构建 debug + release 两个包，默认安装 release**（用户要求：测试优先 release）。
- 构建链：AGP 8.7.2 / Gradle 8.9 / Kotlin 2.0.10 / compileSdk 34 / minSdk 23。
- versionCode = git 提交数，versionName 在 `gradle.properties` 的 `appVerName`（当前 1.2.0）。
- **R8 已对 release 关闭**（`isMinifyEnabled=false`）：本机 AGP 8.7.2 的 R8 8.7.18 处理本项目输入时
  在 graph 遍历处 1020 层自递归 StackOverflowError。已试过：keep 规则二分、`android.enableR8.fullMode=false`、
  `-Xss16m`、去掉 `-overloadaggressively`/`-allowaccessmodification`——全部无效。升级 AGP 或 R8 后可重开混淆。
- proguard-rules.pro 现行内容保留：libxposed/dexkit/dexmaker/data.** 的 keep，**没有** `-overloadaggressively`
  （dexmaker 官方文档：该参数会重命名破坏它生成的 `super$xxx` 桥接方法）。
- gradle-home 特调（`_tools\gradle-home\gradle.properties`）：`-Djava.io.tmpdir` 指到工作区（沙箱拒绝 %TEMP%）、
  `kotlin.compiler.execution.strategy=in-process`（Kotlin daemon 在沙箱下连不上，报 AccessDeniedException 是这个原因，
  **遇到就重跑一次**，不是代码错误）。

## 4. 架构（相对上游 1.1.4 的全部改动）

### 4.1 API 迁移：de.robv → libxposed 102
- 入口：`XposedInit : XposedModule`（onModuleLoaded / onPackageLoaded / onPackageReady）。
- 模块元数据：`META-INF/xposed/{module.prop,java_init.list,scope.list}`（替代 assets/xposed_init）。
- 老 DSL 全部在 `utils/xposed.kt` 用链式 hook 重建（hookBefore/hookAfter/replace/hookAll*），
  统一 `ExceptionMode.PROTECTIVE`（hooker 抛异常只记日志放行原调用）。
- ⚠️ `utils/MethodHookParam.java` 必须保持 **Java 实现**：上游 hook 代码大量
  `param.result.getObjectField(...)` 这种对平台类型的直接点号调用，Kotlin 版编不过。
- `AndroidAppHelper.currentApplication()` → `HookEnv.appContext`（callApplicationOnCreate 里捕获）。
- `XModuleResources` → `AssetManager#addAssetPath` 自建（`HookEnv.loadModuleResources`）。

### 4.2 dex 定位：自研 JNI → DexKit 2.3.0
- 上游的 `app/src/main/jni/qmhelper.cc`（NDK/DexBuilder）已整体移除。
- `utils/DexHelper.kt`：DexKit 门面，**保留旧方法名**（findMethodUsingString 等），
  索引从 long 换成 Class/Member，QMPackage 里 60+ 处调用点不用改。
- 字符串定位走 `batchFindMethodUsingStrings`，每次查询打印诊断：
  `DexKit 字符串定位 [锚点] raw=命中数 ok=可解析数 首个=签名`。
- `libdexkit.so` 由 `utils/NativeLib.kt` 按绝对路径 System.load（宿主进程里 System.loadLibrary
  找不到模块 APK 里的 so），四级兜底。
- **DexSQL MCP 是定位工作的主力工具**（比跑模块快得多）：把 base.apk 拖下来直接 SQL 查
  `classes/methods/method_strings/class_fields` 表。

### 4.3 21.x 定位变化（已适配，锚点对照表见 docs/适配21.0.5.3与API102.md）
- 首页 tab：`timeline/ui/HomePageFragment#h5(x0):Boolean` 闸门（x0.h()=tabId "6"乐馆/"10"直播，
  x0.f()=nativeLoadId），返回 false 即不加 tab。**已实测生效**。
- 简洁模式跳转：`morefeatures.mode.ModeSettingFragmentNew`（旧 ModeSettingFragment 没了）。
- VIP 气泡：`cell.MyMusicBubbleViewHolder#showTaskAndVipBubble`。
- 直播引导：`playernew/view/live/g0`（锚点 `[initLiveGuide]` 仍活）；showCurListen 长锚点已死，子功能降级。
- 音乐世界：cocos 容器，拦 `MusicWorldActivity$Companion.startGame(+$default)`。
- JCE 解锁：PlayerStyleRsp（主题）/ QueryLyricFontRsp（字体）仍活；ApplyIconRsp/GetIconRsp 已下线（分支保留）。

### 4.4 设置入口 + 原生设置页（设备回归见 §6）
- 入口：挂抽屉设置包刷新方法（`settings/packages.b#c`，锚点 `refreshSettingList: FORCE REFRESH`）
  + `BaseSettingPackage#getSettings()` 兜底。两个注入点都只接受「我的 → 更多」对应的宿主设置包，往 `settings` 列表插宿主 Setting 后用 `notifyEvent(0)` 刷新。
  **MuMu 已验证**：「更多」页显示 1 个入口，「更多 → 设置」列表显示 0 个，返回后仍可从「更多」打开原生设置页。
- 原生页（`setting/NativeSettingsPage.kt`）：dexmaker 生成 `BaseRecyclerSettingFragment` 子类
  （覆写 title/settingPackage）+ `BaseSettingPackage` 子类（覆写 createSettingProvider），
  条目 = `SettingProvider` 的动态子类，覆写 `create()` 返回宿主 `Setting$Builder` 构造的原生 Setting，
  开关 = `Proxy(SettingView$d)`。
- DexSQL 核对了 21.0.5.5（7755）的 `SettingProvider(Context, SettingEvent)`。该类在构造时调用 `create()`，调用返回空值会抛异常。
- 代理类自身的构造器钩子只注册一次。打开入口时先准备设置项并构造 Pack，再调用宿主导航方法。Pack 构造失败时直接走 Dialog 兜底。
- 构造器钩子从当前线程取对应 handler。Fragment 依赖宿主在 `addSecondFragment` 调用期间同步构造，21.0.5.5 已验证能打开原生设置页。
- 长异常栈分段时保留 LSPosed 日志转发。排查时同时看模块日志和 logcat。
- Dialog 兜底（`ui/ModuleSettingsDialog.kt`）：原生页不可用时退回自绘面板；标题通过模块资源工具解析，深浅色跟 Q音 皮肤
  （`isBlackSkinInUse`，skinId=901），不是系统 uiMode。

## 5. 调试工作流

```
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\build_and_install.ps1   # 编译+装+lspctl启用+热重载+抓日志
```

- **热重载**：LSPosed 是进程内注入，`am force-stop com.tencent.qqmusic` 再启动即可重载模块，
  **绝不要重启模拟器**（用户明确要求过）。
- 模块启用/作用域 CLI（不依赖点 UI）：
  ```bash
  su -c '/data/adb/modules/zygisk_lsposed/lspctl module enable --user=0 me.kofua.qmhelper'
  su -c '/data/adb/lspd/... lspctl scope set --user=0 me.kofua.qmhelper com.tencent.qqmusic'
  ```
- 日志三处：
  1. logcat（tag=QMHelper，Log.d/E 都在；轮转快，抓要及时）；
  2. `/sdcard/Android/data/com.tencent.qqmusic/cache/log.txt`（save_log 开着时 logcat 全量落盘，
     **每次启动重建**；会很大，grep 用）；
  3. LSPosed 模块日志 `/data/adb/lspd/log/modules_*.log`（root；只有 Log.e 级别走这条通道）。
- ⚠️ **模块配置在 MMKV**：`/data/data/com.tencent.qqmusic/files/mmkv/qmhelper`（21.x 把
  SharedPreferences 后端换成了 MMKV），不是 shared_prefs/qmhelper.xml。清配置删这两个文件。
- ⚠️ **hookinfo.dat 缓存**：`/data/data/com.tencent.qqmusic/cache/hookinfo.dat`（readHookInfo 有
  结构完整性校验——升级模块新增 HookInfo 字段后旧缓存作废重建；再新增字段时把校验加进
  QMPackage 的 cacheStructurallyValid）。
- ⚠️ **adb 点不开 Kuikly 按钮**：「我的」页右上角"更多"、设置页里部分条目是 Kuikly 自绘，
  `input tap` 注入无效，uiautomator 能看到节点但点了没反应。自动化导航到设置入口这条路走不通，
  只能请用户手动点。底栏 tab（首页/视频/刷歌/星光/我的）是原生的，可以点。

2. **真机验证**：用户计划在自己手机上实验（模拟器的 MediaCodec 崩溃是环境问题，
   不加载模块也崩——已确认与模块无关）。
