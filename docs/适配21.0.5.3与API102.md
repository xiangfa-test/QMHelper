# 适配 Q音 21.0.5.3 + 迁移到 libxposed API 102

本文记录这一轮改动的**事实依据**（都是在这台机器上实测/反编译核对过的），方便下次升级时按图索骥，
也方便发布源码时别人能看懂"为什么这么写"。

- 目标客户端：`com.tencent.qqmusic` **21.0.5.3（versionCode 7753）**，Android 15（MuMu，`emulator-5554`）
- 模块基线：上游 `zjns/QMHelper` v1.1.4（2024-01-04，支持到 Q音 13.x）
- 模块版本：`1.2.0`

## 1. API 迁移：`de.robv.android.xposed` → `io.github.libxposed:api:102`

| 老 API | 现在 | 位置 |
| --- | --- | --- |
| `assets/xposed_init` | `META-INF/xposed/java_init.list` | `app/src/main/resources/META-INF/xposed/` |
| `IXposedHookZygoteInit#initZygote` | 取消（zygote 注入没有了） | — |
| `IXposedHookLoadPackage#handleLoadPackage` | `XposedModule#onPackageLoaded` / `#onPackageReady` | `XposedInit.kt` |
| `XposedBridge.log` | `XposedInterface#log`（`HookEnv.log`） | `utils/Log.kt` |
| `AndroidAppHelper.currentApplication()` | `HookEnv.appContext`（`Instrumentation#callApplicationOnCreate` 里捕获）+ `ActivityThread#currentApplication` 反射兜底 | `utils/HookEnv.kt` |
| `XModuleResources.createInstance` | 自建 `AssetManager#addAssetPath` + `Resources` | `utils/HookEnv.kt` |
| `XC_MethodHook` / `XposedHelpers` | `utils/xposed.kt` 用链式 hook 重建的同名 DSL（`hookBefore` / `hookAfter` / `replace` / `hookAll*`） | `utils/xposed.kt` |
| `XC_MethodHook.MethodHookParam` | 同名类，但**改成 Java 实现**（`utils/MethodHookParam.java`） | 见下 |

### 为什么 `MethodHookParam` 用 Java 写

上游一千多处 hook 代码是这么写的：

```kotlin
param.result.getObjectField("alert")?.setIntField("revertTheme", 0)   // 点号调用，没有 ?. / !!
param.result as? MutableList<*>
```

`result` 在老 API 里是 Java 的 `Object`（Kotlin 眼里的**平台类型** `Object!`），所以点号调用合法。
如果这个类用 Kotlin 写，`Any?` 会强迫所有调用点加 `?.` / `!!`，等于把上游代码全改一遍。
用 Java 写，`getResult()` 返回 `Object`，Kotlin 侧又是平台类型，**上游代码一行不用改**。

### hook 语义对齐（`utils/xposed.kt`）

- 前置 hook 里给 `param.result` 赋值（包括 `null`）= 跳过原方法；
- 后置 hook 里 `param.result` 初值是原返回值，赋值即替换；
- `param.args` 是**可变拷贝**，拦截时把它交给 `chain.proceed(args)`，所以改参数生效；
- 统一 `ExceptionMode.PROTECTIVE`：模块自己抛异常只记日志、放行原调用，绝不让宿主崩。

## 2. dex 定位：自研 JNI → DexKit 2.3.0

上游用 `app/src/main/jni/qmhelper.cc`（DexBuilder + 自研索引）做"按字符串找方法"，
配套 NDK/CMake/submodule，发布源码很劝退，且索引是 `long` ↔ `Member` 来回换。

现在 `utils/DexHelper.kt` 是 DexKit 的门面，**保留旧方法名与参数名**（`QMPackage.kt` 里 60 多处调用不用改），
只是把 `long` 索引换成真正的 `Class` / `Member`：

| 旧 | 新 |
| --- | --- |
| `findMethodUsingString(str).firstOrNull()` → `Long` | → `Method` |
| `decodeMethodIndex(x)` / `encodeClassIndex(c)` | 恒等（已经是 `Member` / `Class`） |

字符串定位走 DexKit 的**批量接口** `batchFindMethodUsingStrings`（与 QQMusicPlus 里 `DexKitHelper` 同一套），
并逐条打印诊断日志：`DexKit 字符串定位 [锚点] raw=命中数 ok=可解析数 首个=方法签名`。

`libdexkit.so` 在宿主进程里要按**绝对路径** `System.load`（`System.loadLibrary` 只搜宿主的 nativeLibraryDir），
四级兜底见 `utils/NativeLib.kt`。

## 4. 设置入口与设置面板（21.x 重做）

21.x 里模块**无法**再沿用"代理宿主 `BaseSettingFragment` / `SettingProvider`"的老办法（那些类没了），
所以拆成两层：

- **入口**：挂抽屉设置包的刷新方法，在 `BaseSettingPackage#settings` 里插一条宿主 `Setting`
  （用 `Setting$Builder` 的公开方法构造：`type` / `title` / `subRightDesc` / `click` / `build`），
  随后 `notifyEvent(0)` 让宿主重建列表。
- **面板**：点入口在宿主窗口上弹 `ModuleSettingsDialog`（`ui/ModuleSettingsDialog.kt`），
  内容仍由原来的 `SettingPack.getSettings()` 规格列表渲染（分类 / 开关 / 按钮 / 分割线），
  不依赖宿主任何 Fragment / Provider。

`setting/Setting.kt` 因此被拆成"规格 + `toHostSetting()`"两半：工厂方法只产规格（不会因为宿主类定位失败而返回 null），
需要宿主对象时显式转换。

## 5. 构建 / 验证

```powershell
# 构建 + 安装 + lspctl 启用模块 + 杀掉 Q音 热重载 + 抓 LSPosed 模块日志
pwsh -File tools\build_and_install.ps1
```

- LSPosed 是**进程内注入**：改完只要 `am force-stop com.tencent.qqmusic` 再启动就会重载模块，**不需要重启模拟器**。
- LSPosed 的模块日志在 `/data/adb/lspd/log/modules_*.log`（需 root），模块自己打的 `Log.d` 走 logcat，
  同时被 `save_log` 配置写进 `/sdcard/Android/data/com.tencent.qqmusic/cache/log.txt`（这个最好查）。
- 模块启用/作用域可以用 LSPosed 自带 CLI，不必点 UI：
  ```bash
  su -c '/data/adb/modules/zygisk_lsposed/lspctl module enable --user=0 me.kofua.qmhelper'
  su -c '/data/adb/modules/zygisk_lsposed/lspctl scope set --user=0 me.kofua.qmhelper com.tencent.qqmusic'
  ```
